# AIUI × EverOS 接入方案

本文件是可独立取用的实施路线。它指导助手将现成 JavaScript SDK 接入当前工程；协议字段、宿主 API 与验收细节按下方引用按需读取。

## 先找到现有接线位置

从工程读取目标宿主/固件、Page/Widget/Agent Worker、业务登录与授权代次、已有记忆适配层、记录保存和 outbox。保留应用已经使用的返回结构，不把运动记录或正式业务数据库替换成记忆服务。

确定实际使用 EverOS Cloud v2 还是受保护的自建 v2。多用户分发推荐：

```text
眼镜中的 AIUI 应用 → 同一份 JavaScript SDK
                          │ wx.request + 应用凭据
                          ▼
                 自有认证网关（校验用户/固定数据范围）
                          │ 服务端上游凭据
                          ▼
              EverOS Cloud v2 或受保护的自建 v2
```

个人开发可在运行时提供自己的 Cloud key；公开 AIX 不携带共享 key。账号注册不能替代服务开通、可达网络、认证和隔离。先按 [部署与来源](versions-and-sources.md) 确认版本，再读 [v2 契约](api-v2.md)。

## 应用只需提供的配置

| 接线 | 由应用负责 |
| --- | --- |
| `baseUrl` | 眼镜可达的 HTTPS 网关或明确选定的服务；眼镜的 `127.0.0.1` 不指向开发电脑 |
| `scope` | 稳定的 `{appId, projectId, userId, assistantId}`；它们不代替后端认证 |
| `getAuthorization()` | 同步返回完整运行时认证值，不在源码、AIX、日志或普通缓存放共享主 key |
| `isCurrent()` | 比较实例创建时与当前的业务 owner、会话/授权代次，防止旧任务借新身份继续 |
| 页面/账号清理 | 对应实例调用 `dispose()`；新生命周期需要新实例 |

将完整 `sdk/` 复制到应用 `lib/everos-sdk/`，保留 `package.json` 与 `LICENSE`。所有模块导入同一份实现；根据各自 owner 和生命周期创建适当的 client 实例。不是让所有用户共享一个全局 client。[SDK 用法](../sdk/README.md) · [类型](../sdk/index.d.ts)

## 最小实施顺序

1. 在用户已发起的对话或业务操作读取必要记忆，限长后交给原回答流程；已有相关背景时不重复搜索。
2. 先呈现原业务结果。检索失败、服务拒绝或网络不可用时保留原有能力，不编造历史。
3. 仅保存已获准的事实/对话消息，固定说话者身份和毫秒时间戳；不默认上传全部聊天、GPS 或连续传感器流。
4. 有明确会话边界且确需提取时调用 `flush`。按实际服务状态分别处理排队、缓冲与提取，不把写入回执当成召回结果。
5. 接好账号切换、撤权、hide/unload/destroy 与迟到响应检查。复用当前 outbox；不以新 owner 重放旧用户内容。

宿主调用与清理用 [AIUI 适配](aiui-adapter.md)；请求、返回及错误处理用 [v2 API](api-v2.md)。不要另生成一份 HTTP client。只有目标协议/宿主差异有证据时，才对唯一 SDK 做小范围修正并回归。

## 网关与验证的边界

网关从已验证业务身份确定 owner 和可访问范围；不能信任客户端任意提交的 `user_id`。复用 SDK 所使用的 v2 请求/响应子集，必要时在应用适配层转换原业务结构。SDK 不提供 OAuth 登录、持久队列、服务端鉴权或模型配置。

先在 Skill 根目录执行 `node --test scripts/*.test.mjs`，再验证当前应用的 imports、宿主 API、engine 和 AIX。经授权的独立测试账户分别验证服务读写、提取、检索与跨用户隔离；目标眼镜再验证网络和生命周期。[完整验收与交付模板](verification.md)

没有实服或物理设备证据时，明确列为未执行。安装 Skill、复制 SDK、构建 AIX 和真实接入成功分别报告。
